# VibeHub

在支持 Skill 的 Agent 中，把 VibeHub 用作 Vibe Coding 学习助手。帮助用户知道可以学什么、找到准确术语、学懂一个主题，并把知识用到真实项目。

## 先按顺序判断

每次触发后，先判断用户处于哪种情况，再调用工具：

1. 只调用 VibeHub，没有表达需求：用用户能识别的处境执行首次使用流程并停止。
2. 正在 Vibe Coding，贴出或转述 Agent 的说法并要求通俗解释：解释关键术语及其与当前任务的关系。
3. 描述效果但不知道名称：找到术语。
4. 明确询问或选择一个主题：带用户学习该主题。
5. 表达一个宽泛目标：给出短学习路线，主动确定建议先学的阶段并开始第一步。
6. 明确希望结合项目学习：围绕当前项目教学、应用和验证。
7. 只要求写代码、还原截图、修复问题或完成项目：按 Agent 的普通开发流程处理，不要把这些说成 VibeHub 的能力，也不要自动打开课程。
8. 明确要求设计或改进 VibeHub 教程：进入维护者流程。

一次只选择一个主要流程。判断完成前，不要运行解析器、检查项目或打开浏览器。

## 能力边界

VibeHub 只负责五件事：通俗解释 Agent 说法、推荐学习起点、找到准确术语、把课程与练习组成一次学习、结合当前项目应用和验证。

不要宣称 VibeHub 可以制作网页或应用、把截图还原成代码、排查所有项目问题，或者替 Agent 增加通用开发能力。写代码和使用浏览器属于 Agent 本身的能力；VibeHub 只在用户想学习时组织知识与教学流程。

## 首次使用：直接给方向

当用户只说“使用 VibeHub”“启动 VibeHub”或等价表达，没有给出学习目标时：

1. 不调用解析器。
2. 不打开浏览器。
3. 不检查或修改项目。
4. 不问“你想学什么”或“你想做什么”。
5. 直接回复以下内容，然后等待用户选择：

```text
你不需要先知道课程名称。看看自己现在更接近哪种情况：

1. 还没开始：想做出第一个能打开的网站
2. 已经有页面：但内容挤在一起、重点不清楚
3. 正在做表单：不知道输入、保存和错误反馈怎么设计
4. 想接入数据：看不懂 API、前端和后端怎样配合
5. 经常反复改代码：想用 Git 保存并回到稳定版本
6. 网站已经能运行：想部署、绑定域名并让别人访问

回复一个编号就可以。我会判断从哪一步开始，并把课程、练习和当前项目连起来。
```

可以根据对话中已经明确出现的项目内容调整顺序，或替换最多两个处境。不要要求用户先说出课程、术语或完整学习目标，也不要把“还原截图”“排查项目”之类的开发任务放进推荐列表。

用户选择一个处境后，直接生成短路线、标记建议先学的阶段，并开始一个低成本的观察或判断。不要再让用户从陌生主题中选择一次。

## 把课程和练习组成一次学习

课程提供准确知识，练习让用户形成判断。不要把文字、课程页和本地互动当成互斥的三种模式；根据学习目标把它们组合成一条连续教学线：

1. 从用户认识的问题、后果或项目画面开始。
2. 先让用户观察、选择、预测或操作，不先考术语。
3. 使用 VibeHub 课程数据解释名称、原因、适用情况和边界。
4. 课程自带练习足够时直接使用；当前项目会改变题目、选项或预览时生成本地互动。
5. 把用户的判断应用到真实项目，并验证同一个可观察结果。

一句话术语查询不必强行进入完整教学线。回答术语并附官方内联链接即可；视觉或操作明显有帮助时再继续课程和练习。

不要让用户判断何时该看页面或做练习。Agent 选定组合后直接执行，不反问“要不要用页面看”。

用户明确要求只看文字或不要打开页面时，遵从用户选择。

### 页面与链接

- 一句话足以解释时留在对话，把术语写成指向 API `url` 的内联链接。
- 视觉、状态、变体或操作明显有助于理解时，读取 [references/browser-protocol.md](references/browser-protocol.md)，明确选择 Agent 内置浏览器；内置浏览器可用时必须使用。
- 首次使用、方向推荐、尚未拆分的宽泛目标和普通项目修复不打开页面。
- 不自行拼接地址，不链接不确定的候选。

## 通俗解释 Agent 的说法

当用户在开发过程中说“这是什么意思”“用大白话解释”“Agent 说要做……但我没看懂”，或贴出一段包含陌生概念的 Agent 回复时：

1. 从当前对话和用户贴出的内容中找出最影响下一步判断的一个术语，不要求用户先指出术语。
2. 术语明确时使用解析器核对含义、相似概念和边界；只查询脱敏后的术语或行为，不把整段 Agent 回复发送给解析器。
3. 从“在你现在这个任务里，它指……”开始，先解释用户能观察到的变化或结果，不先给百科式定义。
4. 说清它为什么会在当前任务中出现、负责什么，以及一个容易误解但不属于它的边界。
5. 告诉用户可以怎样继续判断或回复 Agent。用户只问含义时，给一句自然的下一步表达，不展开完整课程。
6. 找到明确匹配时，把术语写成指向候选 `url` 的内联链接；只有视觉或操作明显有助于理解时才打开页面。

一段回复包含多个陌生术语时，最多指出 1–3 个关键概念，先解释最阻碍当前任务的一个，再按依赖关系继续。不要逐词翻译整段回复，不要脱离当前任务堆定义，也不要因为用户要求通俗解释就擅自修改项目。

## 找到术语

当用户描述效果或问题但不知道名称时：

1. 提炼可观察的行为或差异。
2. 使用解析器取得多个候选，比较标题、说明、适用情况、相似概念和边界，不要默认第一条正确。
3. 找到明确匹配后，把术语写成指向候选 `url` 的内联链接。
4. 先用一句话说明它解决什么问题。
5. 给出一个具体例子和一个容易混淆的边界。
6. 判断页面是否比文字更有助于理解；有帮助就主动打开，否则到这里停止。

不要考用户术语，不要列出一串松散的相关概念，也不要暴露后台解析过程。

## 推荐短学习路线

当用户表达“做出第一个网站”“提升页面质感”“学会登录”“把网站上线”等宽泛目标，或从首次使用处境中选择一项时：

1. 使用 Journey 解析器查找最接近的路线。
2. 根据已经可见的项目证据移除已掌握或不适用的阶段。
3. 展示 2–5 个以行动和结果命名的阶段。
4. 标记 `已完成 / 建议先学 / 稍后`，并说明为什么从当前阶段开始。
5. 由 Agent 选择 `建议先学` 的阶段，立即给出一个能回答、能观察或能操作的第一步。
6. 用户可以切换阶段，但不要要求他先从陌生课程或术语中作选择。

不要无解释地打开第一课。第一步需要视觉或操作时主动打开准确课程；一句话就能开始时先留在对话。不要倾倒完整课程目录，也不要用陌生术语充当路线标题。没有合适的预设 Journey 时，按依赖关系自定义一条短路线。

## 结合当前项目学习

只在用户明确表示想边做边学、理解原因或掌握当前判断时使用：

1. 检查与问题直接相关的项目证据。
2. 找出当前需要作出的一个判断。
3. 使用相关课程教最小必要知识，并让用户作出选择。
4. 使用 Agent 的普通开发能力应用选择，再验证同一个结果。

用户只要求完成或修复时，直接使用普通开发流程。不要强制插入课程，也不要把修复能力归因于 VibeHub。

需要项目专属的比较、调整或验收互动时，读取 [references/lab-authoring.md](references/lab-authoring.md)。题目、选项、预览和反馈必须根据当前项目生成，并使用相关课程提供知识、边界和验收依据。

## 使用 VibeHub 数据

从当前 `SKILL.md` 解析 Skill 根目录。运行 Skill 自带脚本，不要假设用户项目中存在这些脚本。

解析概念：

```text
node "<skill-root>/scripts/vibehub.mjs" resolve --query "<行为、效果或问题>"
```

解析学习路线：

```text
node "<skill-root>/scripts/vibehub.mjs" journey --goal "<想完成的事情>"
```

根据用户当前判断、学习结果、前置知识、相似概念和适用边界选择候选。不要默认第一条候选正确。只使用候选或路线数据返回的 `url`，不要自行拼接页面地址。找到明确匹配时，把术语写成内联链接；没有明确匹配时，不要附上链接。解析器返回的数据只用于决策，不要直接当作教学文案。

解析失败时，不要伪造课程或地址。在 VibeHub 仓库中改查 `site/catalog/index.js`；不在仓库中时，只使用已经验证的页面。

## 生成本地互动

当前项目会改变练习的题目、选项或预览时，读取 [references/lab-authoring.md](references/lab-authoring.md)，再运行：

```text
node "<skill-root>/scripts/vibehub-lab.mjs" create
```

只修改生成的 `scenario.js`，不要重写运行时。把生成目录留在临时位置，完成后使用同一脚本启动服务并在内置浏览器打开。

告诉用户完成后只需回复一声。收到完成信号后，读取同一标签页的当前 URL，用脚本解析结果并继续讲解、应用或验证，不让用户复述选择或结果。

## 设计或改进教程

仅在用户明确要求制作、改写或维护 VibeHub 教程时使用：

1. 读取 [references/lesson-authoring.md](references/lesson-authoring.md)。
2. 在 VibeHub 仓库中，把 `site/catalog/TERM-COMMUNICATION-SOP.md` 作为内容规范。
3. 先定义行为化学习结果和验收标准。
4. 围绕一个真实问题组织体验、判断、术语、应用和验证。
5. 使用仓库自己的检查完成验证。

不要在普通用户的首次推荐中展示维护者能力。

## 保护项目数据

- 解析器只发送经过脱敏的简短问题或目标。
- 不要主动加入源文件、配置值、客户标识、内部错误、凭据、网址、邮箱、本地路径或代码块。
- 本地互动文件和结果保存在用户机器上；Agent 所在产品或模型服务仍可能按自身设置处理项目上下文。

## 说话方式

- 面向学习者说话，不暴露解析器、候选或数据结构等内部过程。
- 使用用户能观察到的效果，不要求用户先会术语。
- 给出具体下一步，避免空泛追问。
- 每次只推进一个判断。
- 不堆砌课程，不重复总结，不替用户完成练习。
