# Agent 内置浏览器规范

本规范只管理面向学习者展示 VibeHub 课程页、概念页和本地互动的行为。

## 浏览器选择是硬规则

面向学习者的 VibeHub 课程、概念页和本地互动，必须先尝试 Agent 自己的内置浏览器。

1. 先使用当前浏览器控制能力提供的 `list`、`status` 或 `capabilities` 类只读操作检查可用浏览器；检查阶段不要传入目标 URL。
2. 存在应用内、嵌入式或工作区浏览器时，直接选择它。
3. 不使用基于 URL 的自动选择作为第一步，避免静默切到 Chrome、浏览器扩展或系统浏览器。
4. 如果浏览器工具区分 `in-app`、`embedded` 与 `extension`，明确选择 `in-app` 或 `embedded`。
5. 只有确认内置浏览器不可用或连接失败，才进入后备流程。
6. 用户明确指定其他浏览器时，遵从用户选择。

“优先”不是建议：内置浏览器可用时必须使用。

## 由 Agent 判断是否打开

用户不需要知道什么时候该看页面，也不需要先说“打开页面”。Agent 根据当前学习目标和页面能力主动选择。

同时满足以下条件时，本轮打开一个页面：

1. 用户已经明确要理解的具体主题或问题。
2. 视觉关系、状态变化、变体比较或真实操作明显比纯文字更有帮助。
3. 已经解析并验证一个与当前目标直接相关的页面。

解析器返回 `visualCapabilities` 时，结合学习目标判断 `interactive-detail`、`anatomy`、`variants` 或 `scenarios` 是否能提供理解证据。用户明确要求课程、真实页面或互动，也直接满足第二项。

不需要先征求“是否打开”的许可。打开前用一句话告诉用户要观察或操作什么，页面打开后继续完成教学，不要只做导航。

以下情况不要打开：

- 用户只调用 VibeHub，没有表达需求。
- 正在推荐学习方向。
- 用户提出宽泛目标，但尚未选择当前主题。
- 一句话已经可以回答术语问题。
- 用户只要求开发或修复项目，没有学习意图。

不要用打开页面代替主动推荐，也不要为了展示 Skill 能力自动打开课程。

一句话足以解释时留在对话，并把已经确认的术语写成指向 API `url` 的内联链接。不要自行拼接路径，不要链接不确定的候选。不得用字符图、临时编造的页面或一组链接替代已经决定打开的课程页面。

## 打开方式

1. 使用 VibeHub 解析器取得并验证准确页面地址。
2. 检查当前 Agent 提供的浏览器、内置浏览器或网页预览能力。
3. 存在浏览器控制 Skill 时，先读取并遵守它。
4. 明确选择当前 Agent 工作区中的内置或嵌入式浏览器，不把链接交给通用自动路由决定浏览器。
5. 打开前用一句话说明页面能帮助理解什么，并给出一个观察或操作任务。
6. 一次只打开一个页面；有准确锚点时直接定位到相关部分。
7. 把练习留给用户，不替用户点击并回答。
8. 用户完成后回到对话或真实项目，连接概念、选择和验证结果。

不要使用 `open`、`start`、`xdg-open` 等命令启动系统浏览器。

## 浏览器不可用时

按以下顺序后备：

1. 嵌入式网页预览。
2. 指向准确课程页的可点击链接。
3. 明确说明当前无法打开页面，再使用最小的文字示例继续。

先检查能力，再使用后备。内置浏览器不可用时，不得静默启动外部浏览器；如果只有外部浏览器能够展示，先用一句话说明将切换到哪里，再打开准确页面。用户已经拒绝外部浏览器时，只提供可点击链接或文字解释。不得伪造页面地址，也不要悄悄把用户要求的页面示例换成字符图。

## 本地开发

在 VibeHub 仓库中：

- 优先复用正在运行的开发服务。
- 没有服务时，只在用户任务授权范围内按项目文档启动。
- 从真实运行输出或端口检查中取得地址，不要假设固定端口。
- 展示前验证准确路由可以加载。

教程作者为验证实现而预览页面，属于开发检查，不代表应该把页面自动展示给学习者。

## 互动纪律

- 不为每个陌生词打开页面。
- 不在用户尚未选择主题时打开第一课。
- 不一次打开多个课程标签页。
- 不用术语问答证明用户已经理解。
- 不让课程阻挡紧急修复、安全提醒或用户明确要求直接完成的工作。
- 用户拒绝教学时，立即回到原任务。
- 不只依赖颜色、动画、悬停或声音解释重点。
- 页面与本地互动打开后保留同一标签页，方便后续读取状态和结果。
